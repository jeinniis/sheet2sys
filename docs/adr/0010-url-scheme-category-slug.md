# URL เป็น /{category}/{slug} ไม่มี type ปน

URL ของทุกชิ้นในคลังมีรูปแบบ `/{category}/{slug}` เช่น `/spreadsheet-automation/ทำ-invoice-อัตโนมัติ`
โดย category เป็นโครงหลักของ URL ตามที่ ADR 0008 กำหนดไว้ ส่วน type (Note หรือ Case) ไม่ปรากฏใน URL เลย

เหตุผล: ADR 0003 บอกไว้แล้วว่า Note กับ Case ต่างกันแค่โครงสร้างเนื้อหาภายใน ไม่ใช่ลำดับชั้นที่ผู้อ่าน
ต้องรับรู้ตอนกำลังหาของ ผู้อ่านที่ตามหาหัวข้อหนึ่งไม่ควรต้องรู้ก่อนว่าของที่ต้องการเป็น Note หรือ Case
Case ที่ต้องการโชว์เป็นหลักฐานความสามารถ (ตาม ADR 0003) ไปปรากฏเด่นในหน้า portfolio ที่ query
จาก type field ตอน build แทน ไม่ต้องพึ่ง URL

ทางเลือกที่ปฏิเสธ: `/{type}/{category}/{slug}` ทำให้ URL ยาวขึ้นโดยไม่ได้ประโยชน์เพิ่ม และถ้าของชิ้นใด
เปลี่ยนจาก Note เป็น Case ภายหลัง (หรือกลับกัน) จะต้องย้าย URL ทันที ซึ่งเป็นการทิ้งอันดับที่สะสมมา
เหมือนที่ ADR 0002 เตือนไว้เรื่องวันที่ใน URL ส่วน URL แบบไม่มี category เลยถูกปฏิเสธเพราะขัดกับ
ADR 0008 ตรงๆ

## Consequences

- ของหนึ่งชิ้นย้าย category ไม่ได้โดยไม่เสีย URL เดิม (สอดคล้องกับที่ ADR 0008 ให้น้ำหนักว่า category
  ต้องนิ่งตั้งแต่ต้น)
- หน้า portfolio (list ของ Case ทั้งหมด) เป็นหน้าที่ query ข้าม category ไม่ใช่ route ตาม URL
