# การเขียนของลงคลัง

## ที่อยู่ไฟล์

`src/content/library/{category}/{slug}.md` — โฟลเดอร์ category เป็น convention เพื่อความ
เป็นระเบียบเท่านั้น ตัว URL จริงมาจาก field `category` ใน frontmatter (ดู ADR 0010)

`slug` มาจากชื่อไฟล์เสมอ (ไม่ใช่ frontmatter field) — `named-ranges.md` มี slug เป็น
`named-ranges` **slug ต้องไม่ซ้ำกันทั้งคลัง ข้ามหมวดหมู่และข้าม Note/Case ด้วย** เพราะ
[[wikilink]] อ้างด้วย slug อย่างเดียว ไม่มี category กำกับ ถ้าสองไฟล์ใช้ชื่อไฟล์เดียวกัน
(แม้อยู่คนละหมวด) build จะ fail — ดู docs/architecture.md §5

## Frontmatter

```yaml
---
title: "ชื่อของ"
description: "หนึ่งประโยคสรุปเนื้อหา" # required — โชว์ในหน้าแรก, /tags/, /search/
type: note # หรือ case (ADR 0003)
category: spreadsheet-automation # หนึ่งใน 6 หมวดที่ src/lib/categories.js กำหนดไว้ (ADR 0008)
tags: [google-sheets, apps-script] # อิสระ ไม่จำกัด
created: 2026-09-01 # optional, ใช้ภายในเท่านั้น — ไม่แสดงบนหน้าเว็บ (ดูด้านล่าง)
updated: 2026-09-14 # required — แสดงเป็น "อัปเดตล่าสุด" ไม่ใช่วันเผยแพร่ (ADR 0002)
draft: false # optional, default false — ดู ADR 0011 ก่อนพึ่งพา flag นี้
---
```

`description` เป็น field บังคับ (ใส่ไม่ครบ build จะ fail) — หน้าแรก, หน้า tag, และ
/search/ ใช้มันโชว์ใต้ชื่อของแต่ละชิ้นเพื่อให้ผู้อ่านแยกของออกจากกันได้โดยไม่ต้องเปิดเข้าไปดู

`created` เป็น optional และใช้ภายในระบบเท่านั้น (ไม่ปรากฏบนหน้าเว็บที่ไหนเลย) — เก็บไว้เผื่อ
ต้องใช้ลำดับเวลาจริงในอนาคต (เช่น RSS) โดยไม่ต้องขุดจาก git history ทีหลัง หน้าเว็บยังคงใช้
`updated` เป็นวันที่หลักตามหลัก ADR 0002 เสมอ

`draft: true` ทำให้ของชิ้นนั้นไม่ปรากฏบนเว็บสาธารณะเลย — ไม่มีหน้าให้เปิด ไม่ขึ้นใน /search/,
ไม่ถูกนับเป็นเป้าหมายที่ของอื่นลิงก์ไปหาได้ และไม่ปรากฏเป็น backlink ของของชิ้นอื่น (กลไกหลัก
สำหรับซ่อนของที่ยังไม่พร้อมเผยแพร่จริงๆ ยังคงเป็น private branch ตาม ADR 0011 — ดูหัวข้อ Draft
ด้านล่าง)

## ลิงก์ข้ามของ ([[wikilink]])

เขียน `[[slug-ของอีกชิ้น]]` ในเนื้อหาเพื่อลิงก์ไปหาของอีกชิ้น โดย `slug` คือชื่อไฟล์ไม่รวม
`.md` ใส่ข้อความแสดงเองได้ด้วย `[[slug|ข้อความที่อยากให้แสดง]]`

ระหว่างเขียน (`astro dev`) ลิงก์ที่ยังไม่มีจริงจะเหลือเป็นข้อความ `[[...]]` เดิมในหน้าเว็บ
พร้อม warning ใน log — เห็นชัดว่าพิมพ์ผิดหรือยังไม่ได้เขียนของนั้น **แต่ตอน build จริง
(production) ลิงก์ที่ชี้ไปหา slug ที่ไม่มีอยู่จริง หรือชี้ไปหาของที่เป็น draft จะทำให้ build
fail ทันที** พร้อมบอกไฟล์ต้นทางและ slug ปลายทางที่มีปัญหา — แก้ก่อนถึงจะ build ผ่าน

Backlink ที่ท้ายแต่ละหน้าคำนวณจากลิงก์พวกนี้อัตโนมัติตอน build ไม่ต้องเขียนเอง (ADR 0005)

## Draft

ของที่ยังไม่พร้อมเผยแพร่ให้เขียนใน branch ที่ไม่ push ขึ้น `origin` (ADR 0011) อย่า commit
ลง `main` แล้ว push แม้จะตั้ง `draft: true` ไว้ก็ตาม
